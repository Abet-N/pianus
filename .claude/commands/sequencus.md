## General
This app is in need of a singleton sequencer "Sequnencus", which will be capable of sending commands of format F to a piano generated by htmlGenPiano. The sequencer should be exposed via window.
This component should encode every tone within a system that is first configured with bpm and a rhythm (e.g. 4/4, 3/4, etc.) but will accept finer timings anyways. When the sequencer is used for another song (with potentially another rhythm) it needs to be reconfigured/reinitialized using a function "init".
The core logic should be written into its own file.

## API
Either the sequencer loads a song from local storage, whose values are of the format F, or it can load a midi file (midi generated sequencer programming can be simple for now, but make it easily extendable), or it is iteratively creating a new song taking commands from a user, who consumes an api with the following functions
- newTone(index?): create a tone at the current index (can also create an explicit pause instead)
- deleteTone(index?): delete most recent tone of the current index
- editTone(index): like newTone, but on already existing tone
Both functions can be passed a 2D index parameter, 2D because the first index addresses the nth beat and the second index addresses all beats that start within this beat. Further api cuntions:
- indexStep(forward): jump to the next/previous index (currentIndex++) boolean parameter determines jump direction
- jumpIndex(index): jump to the index passed as parameter
- reviewSong(index?): plays the song in progress. If passed an index, the replay starting point is the index. indexing is 1 dimensional (for now only data of format F is output from the sequencus and there is and should be no direct tonejs api interaction. For now only console.log here)
- stopReview: stops the replay (no api interaction just as for reviewSong)
- saveSong(name?): save current song in localStorage, with the built value in format F
- loadSong(name): load a song saved in localStorage
- deleteSong(name): delete a song from localStorage

## Format
Come up with a human readable Format (F) that can be nicely used to later play Piano (htmlGenPiano, ToneJS api) voices and take into account the tone itself (C, D, D# etc.), amplitude, tone length (full tone, half, quarter), and the voice of the tone (either derived from midi or from this project's available voice names).

## Create Page
As the last step, use the agent to create a page "Sequnencer" dedicated fully to the sequencer. It should consist of UI that takes full advantage of the created sequencus API. Include a button in order to output the sequencer output of sequencus in format F in the console as well as in a fixed localStorage variable. Use a piano, where the user can select the tone, a series of buttons to select the tone length, a dropdown with the voices. These can be set before a tone is deployed (newTone/editTone).
At this point in time also create a VERY simple visualization of the current song (=deployed tones/notes over time) which shall be replaced later.
